## 🎞️ Turn a reference into a shareable Skill package

[Presenter-led examples](../docs/motion-design-examples.md#presenter-motion) connect real speech with captions, screen recordings and motion through three design recipes. Their reference/remix media are upstream demonstrations; new Kinevyn adaptations still need production and review.

[Six animated comparisons](../docs/motion-design-examples.md) show the same motion implementation with different content. Each profile includes `MOTION_DESIGN.md`, invariants and replacement rules, pinned source, a preset and actual render evidence. Contribute the method alongside the project so the next creator can adapt it.

## 🚀 Use a resource

1. Choose a method, a design system or a template for your task. Read its status and source notes.
2. Give its files explicitly to your agent, together with your material and the changes you want. A Brandkit defines identity; a motion design system defines behavior; a template supplies an editable implementation.
3. Continue with the [appropriate production Skill](../docs/skills.md) when making a video. Preview, revise and export through the same project workflow.

The optional library Skills can be selected individually from this checkout:

```sh
npx skills add ./library/skills --skill kinevyn-brandkit
npx skills add ./library/skills --skill kinevyn-design-remix
npx skills add ./library/skills --skill kinevyn-presenter-story
npx skills add ./library/skills --skill kinevyn-growth-teardown
npx skills add ./library/skills --skill kinevyn-design-styles
npx skills add ./library/skills --skill kinevyn-sale-promo
npx skills add ./library/skills --skill kinevyn-spec-sheet
```

For standalone installation or upgrade, use an explicit skills directory:

```sh
node scripts/install-library-skill.mjs kinevyn-design-remix /absolute/path/to/host/skills
```

The helper accepts only the one hundred and four canonical `kinevyn-*` Library names listed in this page. It reuses identical content and refuses to overwrite customized canonical folders. On upgrade, it removes an old forwarding folder only when every file matches the shipped original by hash. Customized folders, extra files and symlinks are preserved and reported in `preservedLegacy` for manual review. Run it for each installed Library Skill, then refresh host Skill discovery. Old Skill invocations are removed; update saved prompts and paths to canonical names.

This library is browsable source today. It is not automatically imported into Studio or registered as MCP resources. The five core production Skills remain in [`skills/`](../skills/); the optional library Skills supply brand context, presenter-story design recipes, a growth-teardown research-to-film method, a design-style library of 21 styles and 2 layouts, three holiday-sale generators (promo, countdown, carousel), 96 single-style recipes or a specific source-remix method and do not add core production routes. The [Studio catalog](../docs/template-catalog.md) and [viewing references](../docs/collections/README.md) retain their existing sources and behavior.

## 🤝 Contribute one useful thing

Copy the [entry checklist](ENTRY_TEMPLATE.md) into a folder under the matching collection. Include what to use it for, editable inputs, an example, attribution, license and the checks you actually performed. Link shared source instead of copying a maintained template into a second location.

Use these status labels in the entry description:

- **Reference:** original work to study, with a source and author.
- **Recipe / draft:** written guidance that still needs project-level verification.
- **Editable example:** source is supplied; state which changes and exports were checked.

Only claim a verified template after recording the project version, adaptation, export and review evidence. A cover image or a successful installation is not that evidence.
